# Endocrine Atlas · 内分泌系统交互图谱

面向初中生的内分泌腺解剖交互可视化。选中腺体 → 相机聚焦 → 阅读知识卡。

## 快速开始

需要 Node.js ≥ 20。

    npm install
    npm run dev        # http://localhost:5173

**没有后端，不用起第二个服务。** 这是一个纯静态前端：依赖只有 react /
react-dom / three，没有任何服务端代码，也没有数据库、API 或环境变量。
7 个器官模型加 1 个人体模型都是 `public/models/` 下的静态 .glb，
Vite 当普通静态资源发出去，`npm run build` 之后 `dist/` 可以直接扔到任何
静态托管上（GitHub Pages / Netlify / Vercel 都行）。

`scripts/` 下那几个是**离线**的模型管线，只在需要重新生成 .glb 时手动跑，
跟运行应用无关 —— 产物已经在仓库里了，克隆下来直接 `npm run dev` 就能看。

## 架构

三层严格单向依赖：

    data/      纯数据，零 import
      ↑
    domain/    纯函数，零 React 零 three
      ↑
    scene/ ui/ React 薄壳

这个方向是刻意的。相机聚焦的数学被挤出 `useFrame` 放进
`domain/cameraFocus.ts`，因而无需 WebGL 就能完整单测 —— 这是
"聚焦时不要贴脸、要保留周边解剖上下文" 这类要求能被自动化验证的前提。

`CameraRig` 只做三件事：读当前机位、推进 `t`、把结果写回 camera 与
OrbitControls。它不含任何数学。

## 坐标系

`+Y` 上 · `+X` 观察者右侧（人体左侧）· `+Z` 腹侧。
原点在双脚之间的地面，模型总高 `1.75` 单位（≈米）。

全部落位数据在 `src/data/glands.ts`，由 `tests/data.test.ts` 校验
落在人体包围盒内、解剖高度序正确、肾上腺（T12）在胰体（L1–L2）之上且更靠背侧。

## 腺体模型：怎么从生成器的输出摆进人体

七个器官模型来自第三方 3D 生成器（Tripo），原始导出每个约 200 万面 / 57 MB，
`scripts/build-organs.sh` 把它们压到每个约 4.5 万面 / 1.5 MB 放进 `public/models/`。

生成器的导出有一个共同约定：**被归一化过** —— 最长边约 1、底面贴 `y = 0`、
水平居中。也就是说模型自带的原点毫无解剖含义。所以每个腺体在数据里声明三件事：

```ts
model: {
  url: '/models/thyroid.glb',
  size: 0.05,                 // 缩放后最长边的真实长度（米）
  anchor: [0, 1.462, 0.022],  // 包围盒中心落在人体的哪一点
  yaw: Math.PI / 2,           // 可选：把生成器的朝向转成 +Z 朝腹侧
}
```

`scene/organPlacement.ts` 的 `placeOrgan()` 用四层 group 兑现它：归心 →
`yaw` → `lateralScale` → 等比缩放并平移到 `anchor`。顺序不能换：归心必须在
旋转**里面**（否则转的是"绕模型原点"而不是"绕器官自身"），`lateralScale`
必须在旋转**外面**（它是非等比的，压的得是世界 X 轴）。

**这份实现只能有一份。** 场景与摆位检查台都调它。早先两边各写了一遍，
加 `lateralScale` 时只改了组件，检查台照旧按老逻辑摆，于是报告说"全部在
体内"—— 而它量的根本是应用不会渲染的另一个摆法。检查台是摆位唯一的裁判，
它一撒谎后面全靠猜。

### lateralScale：唯一允许的非等比缩放

只有大脑用到，用来修生成器给错的比例。这个模型的半脑宽长比是 **0.57**，
真实半脑约 **0.41** —— 厚了四成，按原比例塞不进半个颅腔（实测在右侧颞部
戳出 8 mm）。整体缩小也能塞进去，但前后径会跟着从 17 cm 缩到 12 cm，
那就不是脑的样子了。压左右轴才是对症的：前后径保住，宽度回到解剖值。

### 半个脑该偏在哪一边

大脑模型是**右半脑**的正中矢状切面（要的就是切面：垂体就长在上面，
镜像成整个脑反而会把它永远夹在中间）。`anchor.x = -0.030` 让切面正好落在
中线 `x = 0`，脑组织整个在 `x ∈ [-0.060, 0]`。

正面视角下 `+X` 在画面右侧，所以**右半脑本来就该偏在画面左边**。
摆成左右对称是错的 —— 那等于让半个脑跨到了对侧颅腔里。

### 成对器官不再展开成两份

肾上腺、卵巢、睾丸的模型**本身就含左右两侧**（还连带肾脏、子宫、精索这些
解剖背景），所以一条数据 = 一个模型 = 一个可点对象，点哪一侧都落到同一个
`gland.id` 上。上一版按 `positions` 数组展开成两个 marker 的做法随之取消。

### 垂体为什么用整个脑的模型

垂体只有豌豆大。单给它配一个几毫米的小球，在人体里既认不出来，也说不清它长在
哪儿。大脑模型是一份正中矢状切面，垂体正好在切面上、挂在颅底的垂体窝里 ——
连着颅腔一起给，位置才读得出来。

下丘脑不在这套图里：它不属于初中生物的教学内容，卡片只讲垂体。

## 测试分层

jsdom 没有 WebGL，所以按 "需要多少 3D" 分层：

| 文件 | 工具 | 覆盖 |
|---|---|---|
| `tests/data.test.ts` | Vitest | 数据完整性与解剖不变量 |
| `tests/cameraFocus.test.ts` | Vitest | 聚焦数学，含防贴脸回归 |
| `tests/viewState.test.ts` | Vitest | 人体/详情两种模式的全部状态迁移 |
| `tests/scene.test.tsx` | `@react-three/test-renderer`（无需 WebGL） | 模型落位、缩放、归心、偏航、点击、高亮、材质隔离 |
| `tests/app.smoke.test.tsx` | RTL + jsdom（mock 掉 Canvas） | DOM 层接线与内容一致性 |
| `tests/toolchain.test.tsx` | Vitest | 工具链自检 |

`tests/scene.test.tsx` 把 `useGLTF` 桩成一个 **1×2×4 的长方体、中心放在
`y = 10`**。故意不用以原点为中心的单位球：`OrganModel` 的核心职责就是
"把归一化过、原点毫无解剖含义的模型重新落位"，一个规规矩矩的单位球
测不出这件事有没有做对。

`src/scene/AnatomyScene.tsx`（`<Canvas>` 外壳）是唯一不做自动化断言的
一层 —— 它需要真实 WebGL 上下文。其中的数学已被 `cameraFocus.test.ts`
覆盖，`CameraRig` 只是薄壳。它由浏览器中的人工目视清单验收。

摆位本身**不靠肉眼验收**：`tools/placement.html` 抽样每个模型的真实顶点，
用射线奇偶法判定它在不在人体网格内部，报出体外采样点的个数，同时出四张
对照图。这是"器官有没有戳出体表"唯一可靠的判据 —— 正面看着好好的器官，
从侧面看可能整个穿出了后背。

射线奇偶法有两个必踩的坑：

0. 摆位**必须**调 `placeOrgan()`，不能在检查台里另写一份（见上）。
1. 探针材质**必须** `DoubleSide`。射线从体内射出去打到的是曲面背面，
   `FrontSide` 的材质压根不记这次相交，于是所有内部点都被判成外面 ——
   报告整片飘红，而图上明明好好的。
2. 射线方向**不能取坐标轴**。人体网格关于 x = 0 严格对称，从正中线上的点
   沿 ±X 打出去会正好擦过一整排共面三角形的公共边，相交次数时多时少，
   奇偶随机出错。症状很有迷惑性：肾上腺 381 个采样点里恰好 1 个报体外，
   而那个点就是模型自己的包围盒中心 —— 深埋在体内、最不可能露出来的位置。
   改成几个无理斜向后归零。

## 卵巢与睾丸：为什么需要两种视图

卵巢与睾丸在解剖学上互斥 —— 同一具人体不可能两者兼有。因此：

- **人体上放的是卵巢。** `Gland.display === 'body'` 的 6 个腺体由
  `scene/GlandLayer` 渲染成 marker。
- **睾丸不在人体上。** `Gland.display === 'detail'`，由一个独立的详情
  视图单独承载，可旋转可缩放，左上角有「返回人体」。

`bodyGlands()` 与 `detailGlands()` 是互补的划分，不是包含关系；
`tests/data.test.ts` 锁死了"无遗漏无重叠"以及"人体上有卵巢、没有睾丸"。

### 视图状态

这不是"选中了哪个腺体"，而是模式切换，所以有一个判别联合：

```ts
type ViewState =
  | { mode: 'body'; selectedId: GlandId | null }
  | { mode: 'detail'; glandId: GlandId }
```

全部迁移（`selectGland` / `openDetail` / `exitDetail` / `closeCard`）都是
`domain/viewState.ts` 里的纯函数，`tests/viewState.test.ts` 完整覆盖。
`App.tsx` 只持有一个 `useState<ViewState>`，把事件接到这些函数上。

派生查询把"谁该看到什么"也收进了 domain：`cardGlandId(view)` 决定知识卡
显示哪个腺体（两种模式下都可能有内容），`bodySelectedId(view)` 在详情模式
下返回 `null`（人体场景此刻根本没渲染）。

## 两个 WebGL 层面的坑

**OrbitControls 的阻尼残留。** 拖动结束后 `enableDamping` 会在内部留下
一份 `sphericalDelta`。`CameraRig` 每帧写好机位后调用 `controls.update()`，
这份残留角速度会被重新叠加回去 —— 表现为"点了重置只转回去一半"。
`CameraRig` 在每次起动画前临时关掉阻尼跑一次 `update()` 把它排空
（非阻尼分支会应用一次后将 delta 归零）。

**后台标签页不渲染。** R3F 靠 `requestAnimationFrame` 驱动，隐藏的标签页
里 rAF 不触发，canvas 会停在 HTML 默认的 300×150 且一片空白。调试时若
整个 3D 区是黑的，先确认 `document.visibilityState === 'visible'` 再怀疑代码。

## 两层：人体虚影 / 腺体模型

画面上只有两层，抽象度刻意不同：

| 层 | 是什么 | 可点 | 来源 |
|---|---|---|---|
| **人体** | 半透明女性虚影，菲涅尔玻璃壳 | 否 | MakeHuman CC0 基础网格 + 女性形变表（`scripts/build-body.mjs`） |
| **腺体** | 7 个写实器官 | 是 | 第三方生成器（Tripo）导出的 GLB（`scripts/build-organs.sh`） |

上一版还有第三层"上下文器官"（另画一套肾 / 子宫 / 脑给腺体作位置参照）。
现在不需要了：生成器给的模型本身就带着这些解剖背景 —— 肾上腺连着肾、
卵巢连着子宫、垂体在整个脑的矢状切面上。再画一套只会重复。

### 人体为什么不再是代码生成的

做过两版代码生成：先是「每个部件扫一根管再摆在一起」，后是距离场光滑并集
提等值面。第二版解决了接缝问题（相交实体那些内部面透过半透明壳看得见），
比例也能按人体测量数据排对 —— 但**「好不好看」排不出来**。头是个没有五官的
蛋，手指糊成一团，融合半径一大四肢就和躯干粘死。那是雕塑活，不是参数活。

现在用 MakeHuman 的基础网格：真人扫描拓扑，2020 年 9 月由版权方明确释为
**CC0**（声明写在 base.obj 头部），可直接使用、无需署名。性别 / 年龄 / 人种
在 MakeHuman 里不是骨骼参数，而是一组**逐顶点位移表**（`.target`，每行
`顶点号 dx dy dz`），加到基础网格上就得到对应的人。

## 模型管线

    scripts/build-body.mjs       MakeHuman CC0 基础网格 → public/models/body.glb

### 人体（build-body.mjs）

拉取并缓存到 `vendor/`（不入库），加三张形变表（高加索 / 女 / 青年 / 中等肌肉
体重 / 理想比例），只取皮肤（`g body`，滤掉一百多个 `helper-*` `joint-*`
辅助件），四边形扇形三角化，归一化到脚底贴地、总高 1.75，**切掉双臂**。
18 044 面 / 0.41 MB。

**为什么切臂。** 基础网格是 A 字站姿，两条手臂张得很开 —— 全宽 1.07 m，
其中躯干只占 0.42。它们不承载任何信息，却逼着相机退远，腺体只剩几十像素。

切法是一刀垂直平面。实测这具网格：躯干最宽在髋部、半宽 0.196；手臂在
y < 1.27 处与躯干完全分离、内缘不小于 0.222；再往上并入肩部。取 **0.21**
正好落在这两个数之间 —— 髋削不到，刀口落在三角肌上。不做严格的多边形
裁剪，而是把越界顶点**吸附**到切面、丢掉三角都越界的面：省掉一整套
Sutherland–Hodgman，代价是跨切面那圈三角形被拉扁一点点（网格边长才 5 mm，
看不出来），而刀口是精确平面。断面由补洞那一步封上。

**要删掉网格内部的几何。** MakeHuman 的 base 网格不只有皮肤：眼窝里嵌着一对
实心眼球，嘴唇往里折成一个通到咽部的大空腔。对不透明角色无害，但这里的人体是
一层菲涅尔玻璃 —— 内部面原样透出来，看着就是"脑子和嘴之间浮着一个大球"，
外加一条穿进后脑的隧道。

判据是"能不能从体外走到它旁边"，用体素洪水填充实现：栅格化成 3 mm 体素 →
把墙向外膨胀一格做形态学闭运算 → 从包围盒角上六连通灌水 → 灌到的是体外 →
体外区域再涨回一格 → 三角形碰得到体外就留，否则删。删完露出的眼裂唇缝由补洞
封上。用体素而不是逐三角形投射线：后者要 1.8 万 × 若干方向 × 1.8 万次相交，
没有 BVH 跑不动；体素法是线性的。

这一步有两个顺序 / 参数上的坑，症状都离根因很远：

- **必须先封肩部断面再灌水。** 切臂留下两个开口，不封的话洪水直接从肩口
  灌进整个体腔，"体外"蔓延到全身内部，所有内部面都被判成看得见 ——
  实测只删掉 82 个三角形，眼球和口腔原封不动。
- **必须做闭运算（`seal = 1`）。** 眼裂是敞开的，洪水能从眼缝钻进眼窝、
  绕着眼球转一圈，于是整颗球都算"看得见"。把比 6 mm 更窄的缝糊上之后，
  球才被彻底关在里面。只封肩口不做闭运算时删掉 1287 个三角形（口腔没了、
  眼球还在），加上闭运算是 3052 个。

**z 方向不能按整体包围盒居中。** 脚尖伸得比身体任何部位都靠前、臀部最靠后，
按包围盒对中会把 z = 0 推到躯干前方约 5 cm 处 —— 于是所有按解剖写死的器官
z 坐标集体前移，甲状腺浮到了喉咙外面。改成按**躯干**对中：取胸腹段
（y ∈ [0.95, 1.40]）正中矢状面每层的前后中点，平均后归零。

补洞（边界环填充）在管线里跑两次：切臂后封肩部断面，删内部几何后封眼裂唇缝。
网格必须保持封闭 —— 一旦有开口，半透明壳上会出现黑窟窿，摆位检查台的射线
奇偶判定也会在那一带整个失效。

### 腺体（build-organs.sh）

7 个 Tripo 导出，每个约 200 万面 / 57 MB，压到约 4.5 万面 / 1.5 MB。
`weld → simplify（循环）→ prune → quantize`。两处不显然：

- **要循环调用 simplify**。meshoptimizer 的简化器每次调用只能折叠到某个
  拓扑下限就停（属性缝、边界会锁住一批边），一次 `--ratio 0.02` 实测只掉到
  5%，再跑一次才继续掉。所以脚本反复跑到面数达标为止，而不是相信单次的 ratio。
- **`--error 1`** 把误差预算放到最大，让 ratio 成为唯一约束。腺体在人体里
  只有几厘米大，几何误差在这个尺度上看不出来。

源模型（`Organ/新建文件夹/`，每个 ~57 MB）与 MakeHuman 源文件（`vendor/`）
都不进版本库，`public/models/` 下的产物进。

## 开发用工具

`tools/` 下三个东西只在开发时用，不进构建：

| | 用途 |
|---|---|
| `inspect.html?model=<id>` | 单个模型的正 / 侧 / 顶三视图 + 坐标轴，用来读出生成器给的朝向 |
| `placement.html` | 摆位检查台：逐器官的体外采样点计数 + 人体内的四视图 |
| `head.html` | 用裁剪面把头切开，看皮肤曲面在眼窝 / 口腔处往里折了多深 |
| `scripts/measure-body.mjs` | 打印每个高度上正中矢状面的前后边界与躯干半宽，`anchor` 照它填 |
| `scripts/measure-models.mjs` | 打印每个器官模型的三轴比例、缩放后的实际尺寸与落位后的世界 z 区间，`size` 与前后分层照它核对 |
| `shoot.mjs` | 驱动本机 Chrome 截图。`node tools/shoot.mjs out.png "gland:thyroid"` 会按概览机位把腺体 anchor 投影到屏幕并点击 —— 顺带验证射线检测真能打中 GLB |
