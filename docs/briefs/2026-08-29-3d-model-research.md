## 1. 目标

现在 7 个腺体全部用**同一个发光小球**占位，人体是 capsule/box 拼的中性 mannequin。

需要一份**有依据的方案**，回答：用什么办法把它们换成真实造型，代价多大，风险在哪。

优先级（用户已定）：
1. **首选**：找现成的开源、**带颜色/材质**的解剖模型
2. **次选**：图片转 3D（仓库根目录的 `a8a2c85694a42042a6f1ff05ab5744bd.jpg` 是参考图）
3. 但如果你评估下来**第三条路更优**（例如 Blender 手工做一套风格化低模），请照实说并给出对比 —— 不要为了符合优先级而推荐一个更差的方案

## 3. 硬约束

违反其中任何一条，方案就得重做。

### 3.1 坐标系（`README.md` 有完整说明）

`+Y` 上 · `+X` 观察者右侧（= 人体左侧）· `+Z` 腹侧。
原点在**双脚之间的地面**，人体总高 **1.75 单位**。

模型要么直接按这个系统交付，要么附一个明确的变换矩阵。不接受"到时候在代码里凑"。

腺体模型的**局部原点应落在其解剖中心**，因为 `positions` 是按质心定的，相机也聚焦到质心
（`domain/cameraFocus.ts` 的 `centroid`）。

若你认为某个坐标不对，可以改 `src/data/glands.ts`，但 `tests/data.test.ts` 锁死的三条
不变量必须仍然成立：坐标落在人体包围盒内、成对器官左右对称、解剖高度自上而下有序。

### 3.2 替换点只有一个

`src/scene/GlandMarker.tsx`。它现在渲染统一的 `<sphereGeometry>`，你把它换成按 `gland.id`
分派的真实造型。

`GlandLayer` / `CameraRig` / `GlandSoloScene` / `domain/` / `data/` / `ui/` **不应该需要改动**。
如果你的方案要求改它们，说明接缝选错了 —— 先说明理由再动。

注意 `GlandMarker` 被**两处**复用：人体场景（`GlandLayer`）和单腺体场景（`GlandSoloScene`，
服务于右下角入口缩略图和全屏详情视图）。同一套造型必须在两处都成立。

### 3.3 渲染契约（这条最容易踩）

`tests/scene.test.tsx` 目前断言：

- 人体层的 `Mesh` 总数 **恰好等于 8**（所有 `positions` 之和）
- 每个 position 对应**一个**名为 `gland-marker-<id>` 的可点击对象
- 概览态下所有 marker 的 `material.opacity` **完全一致**（`Design.md` §8：初始不强调任何腺体）
- 选中态：`opacity === 1`、`emissiveIntensity` 更高、`scale.x` 更大
- marker 的世界坐标与 `data/glands.ts` 逐条一致

**如果一个腺体模型是由多个 Mesh 组成的 Group，上面第 1、3 条会直接红。** 两个可选解法，
在方案里明确选一个并说明理由：

- **(a)** 每个 position 仍保留一个不可见的命中代理 Mesh，造型挂在它下面 —— 测试不用改，
  点击命中区可控
- **(b)** 有意修改测试，把"一个 Mesh"的契约放宽成"一个具名可点击 `Object3D`" —— 需要
  同步改 `tests/scene.test.tsx` 并说清新契约是什么

不接受"跑不过就把测试删了"。

### 3.4 视觉层级（`Design.md` §13 §20 §21）

- 人体：半透明、低对比，**不能盖过腺体**。当前是 `opacity 0.15` + `depthWrite={false}`，
  后者是让体内腺体透出来的关键 —— 换成实体网格后必须自己解决同样的问题（深度排序、
  背面剔除、透明排序都可能出问题，这是替换人体最大的技术风险，请在 spike 里实际验证）
- 腺体：概览态统一 0.75，选中 1.0 + 自发光增强
- 风格：**现代教学可视化**，不是医学软件，不是写实 3D 游戏。克制配色，无霓虹

### 3.5 关于"女性人体"——与 `Design.md` §6 的冲突，必须知道

`Design.md` §6 原文明确写了：不要做写实女性身体、不要写实乳房/生殖器/皮肤/面部特征。

用户后来的要求是"女性透明人体"+"阴囊模型"。**这两者不矛盾，但边界要拿准**：

- 女性特征体现在**剪影层面**（胸廓/髋部轮廓），达到生物教材插图的程度即可
- 半透明、无皮肤纹理、无面部五官
- 阴囊做到**解剖示意图**级别，与参考图一致

一句话：**教材插图，不是人体扫描。** 如果候选模型是写实医学扫描数据，需要做风格化处理
再用，或者在方案里说明为什么不做处理也可接受。

### 3.6 体积预算

当前产物（`npm run build` 实测）：

```
dist/assets/index-*.js   1,098 kB │ gzip: 302 kB   ← 几乎全是 three.js
dist/assets/index-*.css      4 kB │ gzip:   1 kB
```

`Design.md` §25 要求"不要巨大的 GLB、不要高分辨率贴图"。目标读者是初中课堂，很可能是
**校园网 + 老旧笔记本**。

建议预算（可以带数据来谈，不能默默超）：

- 全部 3D 资产合计 **≤ 1.5 MB 传输量**（gzip/brotli 后）
- 单个腺体模型 **≤ 60 kB**
- 人体模型 **≤ 600 kB**
- 贴图：能用顶点色就别用贴图；必须用时单张 **≤ 512×512**
- 首屏可交互 **< 3 秒**（模拟 4G / 校园网限速下实测，不是本机 localhost）

格式统一 **glTF 2.0 / GLB**，走 Draco 或 meshopt 压缩。

### 3.7 许可证 —— 一票否决项

这个项目可能会公开部署给学生用。每个候选模型必须记录：

- 许可证名称与来源链接
- 是否允许**修改**（我们必然要改：重新着色、简化、重定坐标）
- 是否允许**商业/机构使用**（学校用途，NC 条款需要单独评估）
- 署名要求的具体写法，以及署名放在页面哪里

**不可接受**：许可证不明、ND（禁止演绎）、来源无法追溯的"网上下的"。
**需要特别注意**：CC-BY-SA 的传染范围 —— 它约束的是模型的衍生作品，还是整个应用？
这一条请给出明确结论，别含糊过去。

## 4. 已知线索（自己核实，别当结论）

开源解剖模型，按我的判断从最可能有用往下排：

- **BodyParts3D / Anatomography**（日本 DBCLS）—— 全身解剖部件库，OBJ，CC-BY-SA 2.1 JP。
  覆盖度最好的一个，但 SA 条款需要按 §3.7 结论化
- **Z-Anatomy** —— 基于 BodyParts3D 的 Blender 开源项目，已整理分层，可能比原始库好用
- **NIH 3D**（`3d.nih.gov`）—— 不少 CC0 / 公有领域
- **Smithsonian Open Access** —— CC0
- **Open Anatomy Project**（SPL / Brigham）—— Slicer 图谱
- **Wikimedia Commons 3D** / **Sketchfab 按 CC 许可证筛选**

图片转 3D（次选路径）：TripoSR、Stable Fast 3D、Meshy、Tripo、Rodin 之类。
**预期要摆正**：这类工具对器官这种无明确视觉先验的形体，解剖准确度通常不够；
更可能适合做人体剪影而非器官。请实测后给结论，不要凭印象。

第三条路（如果你评估更优）：Blender 手工做 7 个风格化低模。优点是许可证完全干净、
体积可以压到极小、风格统一可控；缺点是需要建模工时。**请把它作为对照组认真评估。**
